# 기상청 실제 관측값 연동

## 코드와 배포 상태

개인 프론트·서버 작업 브랜치에서 개발한다. 운영 서버와 회사 저장소는 변경하지 않는다. 기상청 실제 응답을 아직 받지 않았다면 실연동 완료로 표시하지 않는다.

프론트는 기존 대시보드 API 주소의 GET /api/v1/external/weather?latitude=...&longitude=... 를 사용한다. 서버 기능이 미배포면 404, 서버 인증키가 없으면 503이며 화면에 해당 상태를 표시한다. 임의 기상값은 생성하지 않는다.

## 화면

- 왼쪽 현장 기상 탭의 기존 종합정보 패널에서 실제 온도·습도·풍속·풍향, 관측시각(KST), 조회 격자를 표시한다.
- 사건 geometry가 Point일 때 그 좌표를 기본 조회 위치로 사용한다. 지점 좌표가 없으면 사용자가 위도·경도를 입력한다. 임의 지역으로 자동 대체하지 않는다.
- 조회 위치 변경 시 이전 위치의 관측값을 지운다. 같은 위치의 갱신 실패 시 마지막 값과 갱신 지연을 함께 표시한다.
- 5분마다 재조회한다. 서버 캐시 장애 대체값 또는 관측 후 3시간 초과값은 갱신 지연으로 표시한다. 3시간은 초기 표시 정책이며 기상청 제공 주기나 성능 보장값이 아니다.
- 초단기실황의 인근 5km 격자 대표 관측값이다. 실제 풍선 고도·위치의 탑재 센서 측정값이나 특정 관측소값으로 표기하지 않는다.
- 패널은 다른 화면의 모사 모드에서도 모사 기상값을 만들지 않는다. 그 모드에서 지정된 조회 좌표에 대한 실제 API만 요청한다.

## 서버 준비

gxmzung/forest-core-server의 feat/kma-weather 변경과 함께 반영한다. 서버 환경에 KMA_WEATHER_SERVICE_KEY를 설정한다. 공공데이터포털의 기상청 단기예보 조회서비스 이용 승인이 필요하다. 기상청 API허브의 다른 인증키와 혼동하지 않는다.

인증키는 서버 .env 또는 비밀 설정으로만 전달한다. 프론트 VITE 변수·Git·스크린샷·로그에 넣지 않는다. 같은 실제 서버를 로컬과 운영에서 조회해 비교하며 별도 지역·모사 기본값을 추가하지 않는다.

## 확인 순서

1. 서버 단위·HTTP 경로 시험과 프론트 테스트·빌드를 통과시킨다. 표본 응답을 이용한 자동 시험은 실제 기상 응답 확인과 구분한다.
2. 인증키가 있는 개인 검증 서버에서 GET 경로 응답, 출처·격자·관측시각·단위를 확인한다.
3. 브라우저에서 실제 서버를 연결하고 기상청 동일 지역·시각의 자료와 비교한다.
4. 누락값·조회 위치 변경·서버 중단·재접속·404·503을 확인한다.
5. 회사 서버 반영 후 기존 관제 사이트에서 같은 API·좌표로 재검증한다.

자료: https://www.data.go.kr/data/15084084/openapi.do

## 노트북에서 실제 날씨 연결

Core 저장소 feat/kma-weather를 최신 상태로 받은 뒤 npm run start:weather 를 실행한다. 이 서버는 DB·장비 제어 없이 루프백 18891 포트에서 날씨 경로만 제공한다.

프론트 .env.local에 VITE_WEATHER_API_BASE_URL=http://127.0.0.1:18891 을 설정하고 npm ci 후 npm run dev 로 실행한다. 브라우저 주소는 http://127.0.0.1:15173/ 이다. 기상 패널의 위경도에 실제 조회 위치를 입력한다. 나머지 업무·대시보드 API 주소는 운영 기본값을 유지한다.

VITE_WEATHER_API_BASE_URL을 설정하지 않으면 기존 대시보드 API 주소를 사용한다. 따라서 운영 반영 시 로컬 주소를 .env.production에 추가하지 않는다. 로컬과 운영의 날씨 데이터 원본·서버 처리 코드는 같으며 API 실행 위치만 다르다.


## UI 기준 동기화

2026-11-14 회사 저장소 sonjh-github/forest-front-wildfire의 c10eb0b885ef1eebf7bf1e6f81312d15f54fac3b를 UI 기준으로 사용한다. 로고·상단 메뉴·현장 기상 탭·영상·무전·FieldLink와 관련 자산·시험 코드를 함께 가져온다. 개인 저장소의 이전 전체 화면을 회사에 덮어쓰지 않는다. 날씨는 기존 왼쪽 패널에 넣고 별도 우측 하단 플로팅 패널은 사용하지 않는다.

UI 구성 기준이 같아도 조회 시각·지도 이동/확대·선택 탭·화면 크기·브라우저 저장 설정은 다를 수 있다. 이 상태 차이와 코드 차이를 구분한다. 회사 운영 서버는 변경하지 않았다.
