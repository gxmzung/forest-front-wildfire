# 최신 화면 정책: 공공데이터별 수치 탭

전광판 탭·LED 미리보기는 제거했습니다. 현재 기준은 [PUBLIC_DATA_TABS.md](./PUBLIC_DATA_TABS.md)입니다. 아래 이전 전광판 UI 설명은 변경 이력입니다.

# 기상청 실제 관측값 연동

## 코드와 배포 상태

개인 프론트·서버 작업 브랜치에서 개발한다. 운영 서버와 회사 저장소는 변경하지 않는다. 기상청 실제 응답을 아직 받지 않았다면 실연동 완료로 표시하지 않는다.

프론트는 기존 대시보드 API 주소의 GET /api/v1/external/weather?latitude=...&longitude=... 를 사용한다. 서버 기능이 미배포면 404, 서버 인증키가 없으면 503이며 화면에 해당 상태를 표시한다. 임의 기상값은 생성하지 않는다.

## 화면

- 왼쪽 현장 기상 탭의 기존 종합정보 패널에서 실제 온도·습도·풍속·풍향, 관측시각(KST), 조회 격자를 표시한다.
- 사건 geometry가 Point일 때 그 좌표를 기본 조회 위치로 사용한다. 지점 좌표가 없으면 사용자가 위도·경도를 입력한다. 임의 지역으로 자동 대체하지 않는다.
- 조회 위치 변경 시 이전 위치의 관측값을 지운다. 같은 위치의 갱신 실패 시 마지막 값과 갱신 지연을 함께 표시한다.
- 5분마다 재조회한다. 서버 캐시 장애 대체값 또는 관측 후 3시간 초과값은 갱신 지연으로 표시한다. 3시간은 초기 표시 정책이며 기상청 제공 주기나 성능 보장값이 아니다.
- 초단기실황의 인근 5km 격자 대표 관측값이다. 실제 풍선 고도·위치의 탑재 센서 측정값이나 특정 관측소값으로 표기하지 않는다.
- 패널은 다른 화면의 모사 모드에서도 모사 기상값을 만들지 않는다. 그 모드에서 지정된 조회 좌표에 대한 실제 API만 요청한다.

## 서버 준비

gxmzung/forest-core-server의 feat/kma-weather 변경과 함께 반영한다. 서버 환경에 KMA_WEATHER_SERVICE_KEY를 설정한다. 공공데이터포털의 기상청 단기예보 조회서비스 이용 승인이 필요하다. 기상청 API허브의 다른 인증키와 혼동하지 않는다.

인증키는 서버 .env 또는 비밀 설정으로만 전달한다. 프론트 VITE 변수·Git·스크린샷·로그에 넣지 않는다. 같은 실제 서버를 로컬과 운영에서 조회해 비교하며 별도 지역·모사 기본값을 추가하지 않는다.

## 확인 순서

1. 서버 단위·HTTP 경로 시험과 프론트 테스트·빌드를 통과시킨다. 표본 응답을 이용한 자동 시험은 실제 기상 응답 확인과 구분한다.
2. 인증키가 있는 개인 검증 서버에서 GET 경로 응답, 출처·격자·관측시각·단위를 확인한다.
3. 브라우저에서 실제 서버를 연결하고 기상청 동일 지역·시각의 자료와 비교한다.
4. 누락값·조회 위치 변경·서버 중단·재접속·404·503을 확인한다.
5. 회사 서버 반영 후 기존 관제 사이트에서 같은 API·좌표로 재검증한다.

자료: https://www.data.go.kr/data/15084084/openapi.do

## 노트북에서 실제 날씨 연결

개인 Core 저장소 main을 최신 상태로 받은 뒤 npm run start:weather 를 실행한다. 이 서버는 DB·장비 제어 없이 루프백 18891 포트에서 날씨 경로만 제공한다.

프론트 .env.local에 VITE_WEATHER_API_BASE_URL=http://127.0.0.1:18891 을 설정하고 npm ci 후 npm run dev 로 실행한다. 브라우저 주소는 http://127.0.0.1:15173/ 이다. 기상 패널의 위경도에 실제 조회 위치를 입력한다. 나머지 업무·대시보드 API 주소는 운영 기본값을 유지한다.

VITE_WEATHER_API_BASE_URL을 설정하지 않으면 기존 대시보드 API 주소를 사용한다. 따라서 운영 반영 시 로컬 주소를 .env.production에 추가하지 않는다. 로컬과 운영의 날씨 데이터 원본·서버 처리 코드는 같으며 API 실행 위치만 다르다.


## UI 기준 동기화

2026-11-14 회사 저장소 sonjh-github/forest-front-wildfire의 c10eb0b885ef1eebf7bf1e6f81312d15f54fac3b를 UI 기준으로 사용한다. 로고·상단 메뉴·현장 기상 탭·영상·무전·FieldLink와 관련 자산·시험 코드를 함께 가져온다. 개인 저장소의 이전 전체 화면을 회사에 덮어쓰지 않는다. 날씨는 기존 왼쪽 패널에 넣고 별도 우측 하단 플로팅 패널은 사용하지 않는다.

UI 구성 기준이 같아도 조회 시각·지도 이동/확대·선택 탭·화면 크기·브라우저 저장 설정은 다를 수 있다. 이 상태 차이와 코드 차이를 구분한다. 회사 운영 서버는 변경하지 않았다.


## 현장 현재 위치 조회

- `내 현재 위치로 조회`를 누르면 브라우저 위치 권한을 요청하고 받은 좌표로 날씨를 조회한다. 처음 열 때 위치 권한을 자동 요청하지 않는다.
- 위치 기준은 사건 위치 / 이 기기의 현재 위치 / 직접 입력으로 구분한다. 기기 위치나 수동 좌표를 선택한 후 사건 데이터가 갱신되어도 선택을 유지한다. `사건 위치로 조회`로 복귀한다.
- 기기가 보고한 위치 정확도와 확인 시각을 표시한다. Wi-Fi/IP 기반일 수 있으므로 GPS·RTK 고정해 또는 풍선 위치라고 표시하지 않는다. 이 기능은 조회 시점의 위치이며 이동 중 지속 추적은 하지 않는다. 이동 후 버튼을 다시 누른다.
- 위치 조회는 최대 15초 기다린다. 권한 거부·정책 차단·지원 없음·시간 초과·국내 범위 밖이면 기존 조회 위치를 유지하고 직접 입력을 안내한다.
- HTTPS 또는 localhost/127.0.0.1에서 사용한다. 휴대폰에서 노트북의 HTTP 사설 IP로 접속하면 위치 기능이 차단될 수 있다.
- Nginx의 모든 응답 블록에서 `Permissions-Policy`의 geolocation을 `(self)`로 허용한다. 외부 프록시가 추가로 차단하면 해당 배포 설정도 확인해야 한다. 사용자 위치 동의는 별도로 필요하다.
- 자동시험은 위치 성공·권한 거부·시간 초과·미지원·좌표 검사를 확인한다. 실제 노트북 위치 정확도 및 브라우저 권한 동작은 현장 기기에서 추가 확인한다.


## 강수·예보·전광판 미리보기 (2026-11-14)

- 기존 6개 카드 중 강수량에 실황 RN1을 연결하고 `1시간 강수량`으로 표시한다. PTY 강수 형태를 별도로 표시한다. 최대순간풍속·기압은 확보하지 않았으므로 값을 생성하지 않는다.
- 카드 아래에 시간대별 초단기예보를 표시한다. 발표시각과 예보 대상시각을 KST로 구분하며 기온·습도·풍속·1시간 강수 예보를 보여준다. 미수신·권한 오류는 관측값과 독립적으로 표시한다.
- 전국 특보 현황은 접힌 영역에서 원문·예비특보·발표/현황/조회 시각을 확인한다. **현재 위치의 특보 자동 매칭은 미구현**이며 전국 원문을 해당 현장의 경보로 단정하지 않는다. 미수신을 특보 없음으로 표시하지 않는다.
- 한 줄 전광판 미리보기는 실제 수신 관측·예보로만 문구를 만들고 우측으로 이동한다. 조회 좌표·기상청 출처·시각·단위·5km 격자임을 포함한다. 갱신 실패·오래된 자료는 마지막 값임을 표시하고 지난 예보는 제외한다.
- 이동 일시정지/재개 및 전체 문구 확인을 제공한다. 운영체제 모션 감소 설정에서는 애니메이션 대신 가로 스크롤로 읽는다. 실제 LED 전송은 하지 않는다. 패널 도착 후 어댑터에 `weatherTicker()` 한 줄 문자열을 연결한다. 전국 특보는 위치 매칭 전 자동 문구에 넣지 않는다.
- 위치 변경 시 관측값을 조회 좌표와 묶어 관리하고 예보·특보 패널을 다시 마운트하여 이전 위치 값이 새 위치 미리보기에 섞이지 않도록 한다.

### 검증과 남은 확인

표본 응답 기반 API·파서·문구·서버 렌더링 테스트와 TypeScript·프로덕션 빌드·배포 설정 검사를 수행한다. 실제 브라우저 E2E는 작업 환경의 Chromium 실행 제한으로 완료하지 못했다. 노트북에서 우측 이동·일시정지·기기 위치 변경·권한 거부·부분 API 장애를 추가 확인한다.

서버도 개인 저장소 main을 갱신하고 `npm.cmd run start:weather`로 재실행해야 새 예보·특보 경로를 사용할 수 있다. 프론트는 기존 `.env.local` 날씨 서버 주소를 유지한 채 main을 갱신하고 `npm.cmd run dev`로 다시 실행한다. 회사 운영 배포는 별도로 수행해야 한다.

실제 자료 확인 명령: 서버의 `npm.cmd run check:weather:outlook -- 위도 경도`. 기존 키로 초단기예보 서비스 이용 여부를 확인하고 특보 서비스는 별도 활용신청 여부를 확인한다. 실제 응답 확인 전 실수신 완료라고 표기하지 않는다.


## 화면 분리 보완

현장 기상 탭은 기존 강수량 카드(RN1, 1시간 누적)·관측·예보·전국 특보를 표시한다. 최대순간풍속은 현재 실황 API 미제공으로 명시하고 기압 미연동 안내는 숨긴다. 응답에 강수량 필드 자체가 없으면 날씨 서버 업데이트 필요를 안내한다.

전광판 문구·우측 이동 미리보기·일시정지는 왼쪽의 **전광판** 탭에서만 표시한다. 현장 기상과 전광판 탭을 바로 전환할 때 동일한 조회 위치·관측 상태를 유지한다. 실제 패널 전송은 하지 않는다.

프론트만 갱신하고 날씨 서버가 이전 버전이면 실황 기온은 보이지만 강수량 필드는 없으며 예보·특보 경로는 404일 수 있다. 서버 디렉터리에서 main 갱신 후 start:weather를 재실행해야 한다.
